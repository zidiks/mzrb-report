# Отчёт МЗ РБ

Приложение для Windows: выберите выгрузку отчёта из 1С и её вкладку, затем книгу с расчётами и её вкладку, затем нажмите **«Сформировать отчёт»**. Отчёт сохраняется рядом с файлом расчётов в папку «Готовые отчёты». Нужен установленный Microsoft Excel и Windows PowerShell 5.1.

## Установка и обновления

1. Скачайте **mzrb-report.zip** из [последнего релиза](https://github.com/zidiks/mzrb-report/releases/latest).
2. Распакуйте архив в отдельную папку и запустите **Установить.cmd**. Программа установится в `%LOCALAPPDATA%\MzrbReport`, на рабочем столе появится ярлык.
3. В программе нажмите **«Проверить обновления»** и подтвердите установку новой версии. Программа перезапустится сама.

Если Windows блокирует скачанные сценарии, откройте свойства самого ZIP-файла, разрешите его использование после проверки источника и распакуйте заново. Установщик не меняет политики PowerShell и настройки антивируса. Можно также запускать распакованную программу через «Запустить.cmd».

Проверка обновлений выполняется только по кнопке, пока нет другой операции. Загружается последний стабильный релиз этого репозитория, проверяются SHA-256 из GitHub API, версия и состав архива. Перед заменой создаётся резервная копия в `Data/Updates/Backups`. При ошибке копирования прежние файлы восстанавливаются. Никакие файлы отчётов не отправляются в сеть.

## Изменения 1.1.1: автоматическое сопоставление договоров

Обязательный пошаговый просмотр договоров убран. Программа проходит по строкам 1С и находит соответствующий договор в большой книге; различия в написании препаратов и поставщиков больше не требуют ручного выбора строки при однозначном номере договора. Сокращённые названия дистрибьюторского контракта приводятся к одному виду. Если номер повторяется у разных поставщиков или дат, совпадение дополнительно проверяется по реквизитам.

Для найденного договора берутся все рассчитанные суммы выбранного месяца, включая нули. Договор, который есть в большой книге, но не имеет записей за выбранный месяц, получает нулевые месячные суммы. Договор, которого в большой книге нет, сохраняет значения 1С. Правильная разбивка суммы между препаратами в 1С сохраняется. Общие расходы договора записываются один раз в первую заполненную позицию, с очисткой заменяемого поля в остальных строках договора. Перераспределение включается в отпуск существующей строки. При несовпадении общего отпуска и разбивки 1С между несколькими препаратами программа сохраняет разбивку и записывает замечание, не распределяя деньги произвольно.

Результат показывает число обновлённых полей; несопоставленные суммы и замечания включаются в HTML-проверку без обязательного обхода всех пунктов. Входные книги и порядок позиций 1С сохраняются. Пустое наименование можно дополнить из однозначной записи расчётов. Реальные пользовательские книги, их суммы и персональные сверки не входят в исходники и релизы.

## Изменения 1.1.0: два входных файла

Основа отчёта теперь выбирается отдельным полем: это книга, выгруженная из 1С. Её полный список и порядок строк, реквизиты, незатронутые суммы, учреждения и их расшифровки сохраняются. Вторым файлом служит прежняя книга с расчётами. Период в заголовке 1С сверяется с выбранным отчётным месяцем.

Совпадения по договору, препарату, поставщику и дате сопоставляются автоматически. В неоднозначных случаях пользователь указывает номер строки исходной книги 1С. Значение `0` означает явно пропустить сумму; новые позиции из расчётов не добавляются. Пропуски фиксируются в проверке. Отсутствующая месячная запись и пустая сумма не заменяют значение из 1С; явный ноль заменяет. Несколько записей расчётов для одного поля строки сначала суммируются, затем заменяют поле один раз. Перераспределение включается в отпуск той же строки без добавления строк.

Фантомные колонки удаляются с сохранением ширин 13 полей. Если в удаляемой колонке обнаружены данные, экспорт блокируется вместо их потери. Итоги пересчитываются формулами; суммы по учреждениям не прибавляются повторно к ВСЕГО. Выгружается выбранная вкладка в новый XLS. Входные файлы не меняются. В «Проверках» сохраняется HTML со списком замен и пропусков, а сохранённая проверка учитывает оба файла, их вкладки и контрольные суммы.

Для разработки: `tests/Merge.Tests.ps1` проверяет объединение на искусственных данных. `tests/Excel.Merge.Tests.ps1` при наличии установленного Excel проверяет полный цикл создания двух книг, анализа, экспорта, повторного открытия и проверки формул. На CI без Excel эта проверка явно пропускается.

## Изменения 1.0.4

Встроенный `Data/Layout.xls` пересоздан через сохранение в Excel 97–2003 (BIFF8), чтобы устранить проблему открытия шаблона в Excel 2010, которую режим восстановления в 1.0.3 не решил. Проверены все значения ячеек, 1396 объединений, высоты строк и точные ширины 34 колонок. Пакет сохраняет прежний состав файлов и совместим с обновлением из 1.0.2 и 1.0.3.

В `scripts/Check.ps1` добавлена проверка обычного открытия шаблона через настоящий Excel, если он установлен. На GitHub-hosted Windows она явно помечается как пропущенная; для подтверждения Excel 2010 нужно выполнить проверки на компьютере с этой версией Office. При ошибке теперь сохраняются обе причины (обычное открытие и восстановление) и версия Excel.

## Изменения 1.0.3

Окна стали компактнее, подстраиваются под рабочую область экрана с учётом масштаба Windows и позволяют прокрутить содержимое до нижних кнопок. В окне проверки кнопки переносятся на следующую строку.

Если Excel отклоняет встроенный XLS-шаблон при обычном открытии, программа повторяет открытие в штатном режиме восстановления Excel (`xlRepairFile`). Исходные книги открываются только для чтения, без восстановления; настройки безопасности Office не меняются. При повторной ошибке сообщение явно указывает на шаблон. Проверка на реальном Excel 2010 необходима отдельно: CI не содержит Microsoft Excel.

## Правила отчёта

Месяц определяется по дате вкладки: `01.11.26` → октябрь. Отбор строк выполняется **только по колонке 22**: название месяца или номер в метке, например `курс.разн.10`. Суммы берутся из колонки 23, для расшифровки расходов используются колонки 17–21. Неоднозначные распределения требуют проверки пользователя. Итоги в Excel считаются формулами; в результате 13 видимых полей с исходными ширинами. Данные по учреждениям сохраняются из книги 1С.

В публичном репозитории и релизах нет исходных отчётов, финансовых данных, сохранённых проверок и персональных справочников. Пустой `Data/Layout.xls` содержит только оформление и заголовки. Локальные `Data/October.json`, `Data/Names.json`, `Data/Settings.json` и `Data/Work` обновление сохраняет. В режиме двух файлов основой служит выбранный отчёт 1С; прежний октябрьский профиль не подменяет его данные.

## Разработка и выпуск

```powershell
powershell -NoProfile -STA -File scripts/Check.ps1
```

Проверяются синтаксис PowerShell 5.1, загрузка XAML, расчёты на искусственных данных, упаковка, целостность обновлений, откат при ошибке и сохранность персональных файлов. Для этих проверок Excel не требуется; проверка реального оформления и генерации выполняется локально с Excel.

При push в `main` и pull request GitHub Actions проверяет код и собирает ZIP. Для выпуска измените `app/Version.json`, сделайте commit и отправьте тег с той же версией:

```powershell
git tag v1.1.1
git push origin main
git push origin v1.1.1
```

Сборка тега создаст GitHub Release с `mzrb-report.zip` и `SHA256SUMS.txt`. Для сборки и обновлений личные токены не нужны: публикация использует временный `GITHUB_TOKEN`, клиент читает публичные релизы.
